# 小说解析 RAG 系统 — 前端设计文档

> 版本：v1.0（配套《需求分析》《API 列表》《story_sql》）
> 设计技能：design-taste-frontend（反 AI-slop 视觉纪律）
> 技术栈：Vue 3 + Vite + Tailwind v4 + Pinia + Vue Router + ECharts
> 状态：设计阶段。后端未就绪，接口先以 mock 占位，后续切换真实 `/api/v1`。

## 一、Design Read（设计判断）

Reading this as: 一个面向网文作者与研究者的 B2B 工具型 Web 应用（小说解析 RAG 工作台），受众是创作者与研究者，语言为现代中文 SaaS 工作台风格，leaning toward Vue3 + Tailwind + 中性色板 + 单一墨绿强调色 + 左侧导航工作台布局。

三档参数（Dials）：

- `DESIGN_VARIANCE: 5` 工作台需要可预测、对称、信息密度合理，不做艺术化 chaos。
- `MOTION_INTENSITY: 4` 适度过渡动画（路由切换、抽屉、hover），不喧宾夺主，尊重 `prefers-reduced-motion`。
- `VISUAL_DENSITY: 6` 应用类中等密度，信息丰富但不过于拥挤，数据表清晰分隔。

## 二、技术栈选型（均用现成框架，不造轮子）

| 用途 | 选型 | 理由 |
|------|------|------|
| 框架 | Vue 3 + Vite | 需求分析已定 Vue3；Vite 启动快 |
| 路由 | Vue Router 4 | SPA 多页面路由 |
| 状态 | Pinia | 用户态、主题、解析任务进度 |
| 样式 | Tailwind CSS v4 | 原子化，v4 用 CSS `@theme` 定义 token |
| 图标 | `@phosphor-icons/vue` | taste 技能推荐库，统一 strokeWidth 1.5，单一家族 |
| 图表 | `echarts` + `vue-echarts` | 需求明确 M5 图谱、M14 仪表盘用 ECharts |
| 请求 | `axios` | 统一拦截器封装 `/api/v1` + Bearer |
| 流式 | 原生 `EventSource` | SSE 进度/对话/续写（M1.11/M7/M8） |

不引入重型 UI 组件库（避免默认态 slop），基础组件（Button/Card/Table/Modal/Drawer/Input/Tag/EmptyState/Skeleton）用 Tailwind 自建，保持可控。

## 三、视觉系统（Token）

### 3.1 颜色（单一强调色 + 中性基底，明暗双模）

亮色模式：
- 背景 `--bg: #FAFAF9`（stone-50，off-white，非纯白）
- 表面 `--surface: #FFFFFF`，`--surface-2: #F5F5F4`
- 边框 `--border: #E7E5E4`
- 文本 `--text: #1C1917`，`--text-muted: #78716C`
- 主强调 `--accent: #0D9488`（teal-600，墨绿/松绿，知识感，区别于 AI 紫）
- 强调悬停 `--accent-hover: #0F766E`
- 危险 `--danger: #DC2626`，警告 `--warning: #D97706`，成功 `--success: #16A34A`

暗色模式（M13.8 主题切换）：
- 背景 `--bg: #18181B`（zinc-900，非纯黑）
- 表面 `--surface: #27272A`，`--surface-2: #1F1F23`
- 边框 `--border: #3F3F46`
- 文本 `--text: #FAFAF9`，`--text-muted: #A1A1AA`
- 主强调 `--accent: #2DD4BF`（teal-400，暗色提亮）

Color Consistency Lock：全站仅用 teal 作为强调色，危险/警告/成功仅用于语义状态（删除、错误、完成），不滥用。

### 3.2 字体（禁 Inter，自托管优先，先字体栈）

- 西文/数字：`'Plus Jakarta Sans', system-ui, sans-serif`（后续 `next/font` 风格自托管 `@font-face` + `font-display: swap`）
- 中文：`'Noto Sans SC', 'PingFang SC', 'Microsoft YaHei', sans-serif`
- 生产不通过 `<link>` 引 Google Fonts；本地放字体文件。

### 3.3 形状 / 阴影 / 间距（Shape Consistency Lock）

- 圆角分级（有文档规则即允许）：`--radius-sm: 8px`（按钮/输入/标签），`--radius-md: 12px`（卡片/面板），`--radius-lg: 16px`（抽屉/大容器）
- 阴影：tint 到背景色相，不用纯黑投影，如 `0 1px 3px rgba(28,25,23,0.08)`
- 间距：4 / 8 / 12 / 16 / 24 / 32 体系

### 3.4 主题锁

全站单一主题（亮或暗，跟随 `prefers-color-scheme`，提供手动切换并存本地）。禁止中途翻转到反色模式。

## 五、布局系统

### 5.1 应用框架（AppLayout）
- 左侧固定 Sidebar（按模块分组：工作台/小说/知识库/切片/图谱/人物/对话/续写/模型/Skill/MCP/Prompt/扩展），可折叠，单色图标 + 文字，激活态用 teal 左条 + 浅底。
- 顶栏：面包屑 + 全局搜索（M13.1）+ 主题切换 + 用户菜单。单线渲染，高度 64px。
- 内容区：`<router-view>`，`max-w-[1400px] mx-auto`，移动端单栏。

### 5.2 登录框架（AuthLayout）
- 全屏居中卡片，左侧品牌叙事 + 右侧表单（或上下分栏），不堆砌装饰。

### 5.3 解析进度悬浮窗（M1.11）
- 右下角 Drawer/小窗，SSE 推送阶段文案 + 进度条 + 百分比，可最小化到后台，完成自动关闭并刷新列表。不阻塞主操作。

## 六、组件规范（反 slop）

- 按钮：主按钮 teal 填充 + 白字（对比度达标）；次按钮 outline/ghost；`:active` 微下移 `translate-y-[1px]`。禁止白底白字。
- 卡片：仅在有层级需要时，否则用 `border-t` / `divide-y` / 留白分组。
- 数据表：切片/日志等用清晰行分隔 + hover 高亮，不用每行上下双边框。
- 空态：有引导文案与首要操作（如「还没有小说，点击上传」）。
- 加载：骨架屏匹配最终布局，避免圆形 spinner。
- 表单：label 在上，错误在下，focus ring 用 teal。
- 图标：仅用 Phosphor，strokeWidth 统一 1.5，单一家族。
- 移动端：所有多列布局 `< 768px` 显式折叠为单栏。

## 七、接口占位策略（先写接口，后端后续）

1. `src/api/http.js`：axios 实例，`baseURL=/api/v1`，请求拦截注入 Bearer，响应解包 `{code,msg,data}`。
2. `src/api/<module>.js`：每个模块一个文件，函数签名严格对应《API 列表》（novels.js / knowledgeBases.js / chunks.js / graph.js / characters.js / conversations.js / writing.js / llmConfigs.js / skills.js / mcp.js / prompts.js / dashboard.js / files.js / auth.js / explore.js）。
3. `src/mock/<module>.js`：假数据；通过 `VITE_USE_MOCK` 开关，在 `http.js` 层拦截返回 mock。后端就绪后关闭开关即接真实接口。
4. SSE：封装 `useSSE()` composable，基于 `EventSource` 消费 `/parse-tasks/{id}/progress`、`/conversations/{id}/messages`、`/novels/{id}/continue-write`。
